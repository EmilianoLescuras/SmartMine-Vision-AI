# experiments/

Stores results from training runs and hyperparameter experiments.

Each experiment is a self-contained folder with logs, metrics, and config snapshots. This enables reproducibility without rerunning expensive training jobs.

---

## Structure

Each experiment run generates a folder:

```
experiments/
└── ppe_v1/
    └── baseline/
        ├── args.yaml          ← Training args snapshot (auto-generated by Ultralytics)
        ├── results.csv        ← Per-epoch metrics
        ├── results.png        ← Loss and metric curves
        ├── confusion_matrix.png
        ├── weights/
        │   ├── best.pt        ← Best checkpoint by mAP50
        │   └── last.pt        ← Final epoch checkpoint
        └── val_batch*.jpg     ← Validation prediction samples
```

Ultralytics saves this structure automatically when `project` and `name` are set in the training config.

---

## Naming Convention

`experiments/{task}_{version}/{run_name}/`

Examples:
- `experiments/ppe_v1/baseline/`
- `experiments/ppe_v1/lr_sweep_01/`
- `experiments/vehicles_v1/baseline/`

---

## Tracking Strategy

| Phase       | Tool                      | Purpose                              |
|-------------|---------------------------|--------------------------------------|
| Phase 1–2   | Ultralytics auto-logs      | CSV metrics, weight checkpoints      |
| Phase 3+    | MLflow (planned)           | Centralized experiment registry      |

MLflow will track: parameters, metrics, artifacts, and model versions across all experiments.

---

## What NOT to Commit

- `weights/` folders — large binary files, store in cloud storage.
- `val_batch*.jpg` — auto-generated visualization images.

Commit only:
- `args.yaml` — config snapshot
- `results.csv` — metrics history

Add other large artifacts to `.gitignore`.

---

## Reproducibility

To reproduce an experiment:
1. Copy `args.yaml` to `configs/training/`.
2. Run: `yolo train cfg=configs/training/args.yaml`
3. Results will appear in `experiments/` under the configured `project/name`.
